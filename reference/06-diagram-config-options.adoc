= Reference 6: Diagram Configuration Options

The User Guide includes auto-generated UML class diagrams for each API resource. The default diagram set can be customised by creating a configuration file in the API's documentation directory.

== Configuration File Location

  documentation/diagrams/config.yaml

This file is optional. If it does not exist, the tooling uses default behaviour.

== Options

[cols="1,1,3", options="header"]
|===
|Option |Type |Description

|`ignorePaths`
|array of strings
|API paths that should not generate diagrams. Default: `["/listener/"]`. Useful for excluding notification listener endpoints from the diagram set.

|`simpleTypes`
|array of strings
|Resource names that should appear as simple type references in diagrams rather than being expanded into full class boxes. Use for common utility types like `Money`, `Quantity`, `TimePeriod` that would otherwise clutter every diagram.

|`includeAllRulesResources`
|boolean
|If `true`, every resource from the rules file is included as a top-level diagram. Default: `false`. Useful for APIs where some resources are not directly in the OAS paths but should still be documented.

|`autoIncludeSubclassResources`
|boolean
|If `true`, discriminator subtypes are automatically included as top-level diagrams if their parent resource appears in the OAS paths. Default: `true`.

|`includeRulesResourcesMatching`
|array of strings (may include regex)
|Include only resources whose names match any of the given values or patterns. Example: `["^WsBb"]` to include all resources starting with `WsBb`.

|`excludeRulesResourcesMatching`
|array of strings (may include regex)
|Exclude resources whose names match any of the given values or patterns. Example: `["^Product$"]` to exclude the `Product` resource specifically.
|===

== Example

[source,yaml]
----
ignorePaths:
  - /listener/
simpleTypes:
  - Money
  - Quantity
  - TimePeriod
includeAllRulesResources: false
autoIncludeSubclassResources: true
excludeRulesResourcesMatching:
  - "^AbstractBase$"
----
