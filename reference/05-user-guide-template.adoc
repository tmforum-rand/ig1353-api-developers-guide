= Reference 5: User Guide Template Structure

The User Guide is automatically generated from the rules file, JSON schema descriptions, and example files. This page documents what controls the content of each section, and the cover page fields that must be set manually.

For the generation workflow, see xref:../runbooks/07-generate-user-guide.adoc[Runbook 7: Generate and Review the User Guide].

== Generated Sections and Their Sources

[cols="2,3", options="header"]
|===
|Generated section |Content source

|Cover page
|Fields in `documentation/userguide.adoc` (set manually — see below)

|Table of Contents
|Auto-generated from the document structure

|API Overview
|`api.description` in the rules file

|Resource Definitions
|`resources[].name` + entity `description` from the JSON schema file

|Attribute Descriptions
|`description` fields on properties in the JSON schema files

|Required/Restricted Parameters
|`requiredParameters` and `parameterRestrictions` in the rules file

|Operation Constraints
|`required: true` settings in `supportedHttpMethods`

|UML Diagrams
|Auto-generated by the PlantUML tooling; configurable via `documentation/diagrams/config.yaml`

|Operation Examples
|Example files referenced from the rules file

|Notification Examples
|Example files referenced from the notifications section of the rules file

|Auxiliary Diagrams (lifecycle, state transitions)
|PlantUML files in `documentation/diagrams/` — hand-authored
|===

== Cover Page Fields

Set these fields in `documentation/userguide.adoc`:

[cols="1,1,2", options="header"]
|===
|Field |Format |Description

|`:RELEASE-STATUS:`
|`Preview` or `Production`
|The document's release status. Use `Preview` during development; update to `Production` when the API is published.

|`:MATURITY-LEVEL:`
|`General availability (GA)`
|Fixed value for published TMForum APIs.

|`:TEAM-DATE:`
|`dd-Mmm-yyyy` (e.g., `15-Apr-2025`)
|The date the team or architect approved this version of the document.

|`:APPROVAL-STATUS:`
|`Team Approved`
|Fixed value once the API has passed team review.

|`:IPR-MODE:`
|`RAND`
|Fixed value. RAND = Reasonable and Non-Discriminatory licensing terms.

|`:VERSION:`
|e.g., `5.1.2`
|The full SemVer version of this API.
|===

== Entity and Attribute Description Quality

Because the User Guide pulls `description` values directly from JSON schema files, the quality of the generated documentation depends on description quality in the schemas. Key rules:

* Write descriptions as if they will appear as a standalone tooltip — no context from the rules file is available to the reader
* Do not refer to specific API names, JIRA tickets, or implementation details
* Aim for one clear sentence describing what the entity or attribute *is*, not how it is *used*
* See the GUIDANCE.md file in this repository for the full description quality guidelines
