=== 2. Write or Update Entity Examples

For each resource, provide at least one example of the complete entity payload. Requirements:

* All required fields must be present
* `id` and `href` must be consistent: `id` must equal the last path segment of `href`
* `@type` must be populated with the entity name
* `@referredType` must be populated in all `<Entity>Ref` examples
* Use realistic values, not `"string"` or `"12345"`

=== 5. Validate All Examples

. In the Express WebUI, select your API.
. Open the *Examples* tab.
. Click to validate examples.
. Fix any validation errors and re-run until no errors remain.

Validation errors indicate that an example payload does not conform to the generated OAS schema. Common causes:

* A required field is missing from the payload
* A field value does not match the declared type or format
* An `$ref` resolves to an unexpected schema

== Expected Outcome

All examples validate without errors in the Express WebUI Examples tab. `id`/`href` values are consistent throughout. No placeholder strings remain. Notification examples follow the payload content rules for each event type.

== Common Errors

* *`id` and `href` inconsistent*: The `id` value must exactly match the final path segment of `href` (everything after the last `/`).
* *`@referredType` missing from a Ref example*: Every `<Entity>Ref` object must include `@referredType` set to the name of the referred entity type.
* *Example fails validation but OAS looks correct*: The OAS may contain an `allOf` that imposes additional required fields inherited from a base entity (e.g., `Entity`, `Addressable`). Check those base schemas.
